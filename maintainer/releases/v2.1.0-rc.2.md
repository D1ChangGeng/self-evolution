# Self-Evolution v2.1.0-rc.2

This release candidate adds guarded knowledge edits and portable task
continuation, improves lifecycle/source review, and introduces an executable
engineering evaluation suite. It is published for evaluation; stable-release
model-effectiveness evidence remains pending.

## Changes

- Resolve archived Decision IDs while keeping current retrieval limited to
  active Guides and accepted Decisions. Detect invalid supersession and compare
  Guide routes by scope, purpose and consumer conditions.
- Report affected source paths, baselines and review limits in text/JSON output.
- Add `kb write <document> <proposal> <expected-sha256|absent>` with participating
  Windows/Linux process locks, conflict detection and interrupted-write recovery.
- Provide optional `continuation/1` guidance and a template, including actual
  patch transfer, branch/base checks and stale verification handling.
- Focus standing Skill instructions on project engineering work. Initialization
  remains three files; adapters remain disabled by default.
- Add 24 executable A/B engineering scenarios, six baseline preparation paths,
  three-session refactor chains, eight curated public history pairs, subprocess
  transfer tests and raw evidence/cost derivation.
- Cover complete smoke workspaces, actual executable version/hash and valid
  knowledge schemas. Reject receipt replay, arm relabeling and missing controls.

## Validation and evidence boundary

Publication requires clean-install CI, type/format checks, CLI tests, engineering
catalog/runner tests, legacy migration/evidence checks, and distribution bundle
verification on the released commit. GitHub Actions records Linux and Windows
results for that commit.

The offline suite uses deterministic fake CLI processes and synthetic fixtures.
It demonstrates implementation and orchestration behavior, not model quality or
automatic Capture benefit. Native-memory controls, fresh paired model campaigns,
independent review and real cross-harness engineering effects remain pending.
The stable `standard`, `private` and `continuity` gates retain their requirements.

## Install and verify

```text
npx skills add https://github.com/D1ChangGeng/self-evolution/tree/v2.1.0-rc.2 --skill self-evolution -g -y
```

Alternatively, verify `SHA256SUMS` and extract the attached ZIP. The
`self-evolution/` directory contains the Skill, bundled CLI, references, license,
usage and migration documentation. Node.js 22+ is required for CLI operations:

```text
node <skill-dir>/references/bin/kb.mjs init --project-root <project>
node <skill-dir>/references/bin/kb.mjs check --project-root <project>
```

Back up the current installation before replacing it. Restore that installation
to roll back the Skill; project knowledge is ordinary repository content and
retains its normal Git history. Existing v1-to-v2 migration/rollback support
remains part of the 2.x contract. Direct editors still use Git conflict handling;
guarded writes cover participating CLI entry points only.
